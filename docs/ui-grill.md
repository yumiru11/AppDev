# AppDev UI 设计 Grill 完整访谈提纲（v2 · 详细版）

> **目的**：这是把你脑海中的界面「翻译」成可执行设计规格的完整访谈。每一题都给出**为什么问**（背景）、**选项实际长什么样**（视觉/交互差异）、**可以联想什么**（参照物），方便你构思。
> **读法**：逐题回答。标注 🔴 = 关键分叉（答偏全盘都偏）；标注 🆕 = 上一版新增。你可以答「A」「选 2」或直接自由描述；没想好的写「待定」不阻塞。
> 回答完我会：① 根据答案产出**视觉规格**（每个页面的具体布局/尺寸/颜色值）② 更新 docs/ui-design.md ③ 拆成多张 UI ticket。
> 配套：`FEEDBACK.md`（真机反馈）· `docs/research/webview-material-you-fusion.md`（WebView 能力调研）· `docs/ui-design.md`（当前设计文档）

## 0. 写给用户的「如何构思」指南（先读这段）

回答设计问题时，有一个好用的大脑模型：**「先整体后局部、先常态后异常、先功能后细节」**。

- **整体**：这个 App 的第一屏长什么样？扫一眼看到什么？（布局骨架）
- **常态**：数据正常加载、正常滚动、正常点击时，每一步给我什么样的感觉？（交互节奏）
- **异常**：加载中、空数据、加载失败、断网、深色模式、超大字体——这些「边角时刻」也要想，因为 80% 的「不好用」都发生在这些时刻。
- **细节**：一行字多大、卡片圆角多圆、图标多粗、动画多快——这些是「质感」所在，可以放到最后凭感觉定。

回答时**不需要技术正确**，只需要描述「你想要的效果」；「能不能做」「怎么做」是我的事（调研文档已覆盖技术可行性）。

## 一、整体布局与导航（全局骨架）

### A1 🔴 底部导航：3 个分区到底是什么关系（真机走查核心分歧）
- **背景**：你上次说「底部那些不是单独弹出的窗口，而是左右切换的分区」，我已改成 HorizontalPager 左右滑切 + 底部 3 Tab。但「分区」的感觉还可以更细——
- **A1-1**：3 个分区（首页/仓库/我的）在你脑子里是哪种模型？
  - A. **并列抽屉式**：左右滑动像翻书，3 页平等，无主次（现在的实现）
  - B. **首页为家的放射式**：首页是主战场，仓库/我的更像「从首页进入的次级页」，左右滑只是快捷方式
  - C. 其他（请描述）
  - 描述：A 适合「3 个功能权重差不多」；B 适合「首页才是核心，其他是配套」。GitHub App 是 A 的变体（底部 4 Tab 平铺）。B 站 App 更接近 A 但首页内有自己的 Tab 叠层。
- **A1-2**：左右滑动手势的**边界行为**：在第一页（首页）继续右滑——
  - A. 无反应（到头了弹一下，overscroll）
  - B. 触发返回上一级页面（手势返回）
  - C. 无所谓
  - 描述：这决定「返回」手势的层级一致性（系统返回 vs App 内分区切换）。
- **A1-3**：切分区时**顶栏与内容一起横移**，还是顶栏固定、只有内容区横移？
  - 描述：一起横移 = 更强的「一整页」整体感（iOS 风格）；顶栏固定 = 更强的「应用外壳」感（Android 风格）。B 站是内容区移、顶栏的小组件跟着上下文变化。
- **A1-4**：分区切换的**动画速度与曲线**感觉：跟手（拖动时内容跟指走）还是松手补一段动画（Pager 的 snap）？要不要「旁边的分区露出一条边」作为视觉诱饵（预示可以滑）？

### A2 🔴 顶栏结构（每屏的「帽子」）
- **背景**：现在顶栏 = 胶囊搜索框 + 通知铃铛 + 头像（T3 骨架搭的）。但「每个分区各自的顶栏长什么样」还没定。
- **A2-1**：**首页**顶栏元素从左到右的排列，你心里的顺序是？
  - A. [胶囊搜索框] [铃铛] [头像] （当前）
  - B. [App 名字/logo] [胶囊搜索框] [铃铛]
  - C. [胶囊搜索框占满] （铃铛/头像移到右侧次级行）
  - D. 其他
  - 描述：搜索框多宽？B 站是搜索框占正文宽度 + 右侧相机 icon；GitHub App 顶栏纯标题 + 右侧头像，搜索走图标。你更接近哪个？
- **A2-2**：搜索框是「**常驻的可点胶囊**」（点击→跳搜索页，自己不可输入）还是「**常驻的可输入框**」（顶栏直接打字）？
  - 描述：可点胶囊 = 轻量、省空间、搜索页有完整 UI（历史/热门/过滤）；可输入 = 少一步跳转但顶栏膨胀。B 站首页搜索框是「可点假输入框」（点击进搜索页）。
- **A2-3**：进入搜索页之后，顶栏**变成什么**？（自动聚焦的输入框 + 取消按钮 + 联想列表？）
- **A2-4**：未读通知红点：铃铛上的数字角标（≥99 显示 99+）还是小红点？点击后角标何时消失（进面板就消失 / 全部已读才消失）？
- **A2-5**：不同分区顶栏是**同一套组件换标题**，还是每个分区可以有**自己的操作按钮**（如仓库分区顶栏右侧出现「+」新建入口）？

### A3 通知面板（全屏滑入层）
- **背景**：已定 = 铃铛触发、全屏滑入面板（不进底部 Tab）。但面板的「性格」未定。
- **A3-1**：滑入**方向与遮罩**：
  - A. 右侧滑入 + 全屏（无遮罩，盖住一切）
  - B. 右侧滑入 + 半透明遮罩（原页面隐约可见、变暗）
  - C. 底部上滑 + 全屏
  - 描述：B 的「隐约可见」贴你的玻璃拟真美学（背后内容虚化）；C 更像 iOS 通知中心。你上次说「毛玻璃要玻璃到背后」，B 的面板背景正好可以做毛玻璃（模糊掉背后的 App）。
- **A3-2**：面板内**分组的骨架**：
  - A. 按仓库分组（每个仓库一个小标题，下辖事件）
  - B. 按时间分组（今天/昨天/本周/更早）
  - C. 平铺列表（不分组）
  - 描述：GitHub 网页的通知 = 平铺（每条显示「所属仓库 + 事件类型」），未读有蓝点。按仓库分组的优点是指向明确（「我的 AppDev 仓库有新 PR」）。
- **A3-3**：每条通知的可点击性：点击 → 直接进对应页面（issue/PR/仓库）？可以左滑操作（标已读/静默仓库）？
- **A3-4**：分组折叠：仓库分组可折叠（收起该仓库的全部通知）？
- **A3-5**：加载/刷新：进入面板即拉取最新；顶部下拉刷新？「全部已读」按钮放哪（顶栏右侧 / 面板底部）？

### A4 🔴 全局背景与玻璃拟真（本次最重要的新方向）
- **背景**：你说过想要「全局背景图等美化」，且明确「现在的毛玻璃（只模糊顶/底栏）不是我要的」。技术调研已确认：背景图放 Compose 层 + 透明 WebView 透出可行；毛玻璃与 WebView 内容之间有物理边界（无法模糊 WebView 像素，见调研文档 §3）。所以以下问题决定「看起来像什么」。
- **A4-1**：背景的**素材类型**：
  - A. **静态图片墙纸**（内置若干张高品质图，用户可换；或用户相册自选）
  - B. **程序化渐变**（随主题色动态生成的柔和渐变/光晕——Every 壁纸那种）
  - C. **纯色 + 轻微纹理**（如细噪点/网格，几乎看不出来但拒绝死板）
  - D. A+B 组合（默认程序化渐变，可换图片）
  - 描述：A 个性强但和 Material You 动态色容易打架（图上颜色会冲）；B 与动态色 100% 协调、永远不脏；C 最克制但最不容易「惊艳」。GitLab/某类「个性化启动器」App 常用 A；Google 自家（如 Pixel 的 Live Wallpaper）倾向 B。
- **A4-2**：背景的**显示范围**（哪些页面透出背景）：
  - A. 全 App 统一（首页/仓库/详情/设置全透）
  - B. 仅一级页（首页/仓库/我的）透出；二级详情页用纯色（可读性优先）
  - C. 仅首页
  - 描述：全透最有「沉浸感」但长文本页（README/Issue 详情）背后有图会干扰阅读；B 是「壳美、内容净」的折中。你倾向哪种？README 阅读时你又希望背景是什么样？
- **A4-3**：背景与内容的**对比处理**（重点考虑可读性）：
  - A. 内容区加一层半透明「纸面」衬底（如 70% surface 叠在背景上），背景只在边缘/卡片间隙露出来
  - B. 背景图本身就压得非常暗/非常淡（低对比），内容直接浮在图上
  - C. 卡片全部法实底（不透），背景只出现在列表间隙/顶栏区域
  - 描述：A = 背景是「氛围」不是「舞台」，是目前阅读类 App 的主流；B = 背景是「陪衬」，需要图片选得极素；C = 最克制，背景只在「缝隙」里发光，类似某些玻璃拟真启动器。
- **A4-4**：**深色/浅色下背景的差别**：深色下背景**自动压暗到什么程度**（近乎全黑只留一点光晕？还是反相变暗图？）；浅色下保持明亮？OLED 主题下背景**彻底消失变纯黑**还是保留微弱底色？
- **A4-5**：背景的**动效**：切主题时背景跟着 Crossfade？背景随列表滚动有**轻微视差**（滚得比内容慢）还是要完全静止跟随（背景固定、内容滚过）？
- **A4-6**：**毛玻璃的正确场景清单**——请逐个拍板，以下哪些位置应该有玻璃效果：
  - [ ] 顶栏（模糊滚过的内容）
  - [ ] 底栏（模糊滚过的内容）
  - [ ] 通知面板背景（模糊背后的 App）
  - [ ] 底部弹出面板（BottomSheet，如分享/更多操作）
  - [ ] 图片查看器背景
  - [ ] 悬浮操作按钮（FAB）区域
  - [ ] 设置页分组头
  - [ ] 卡片本身（卡片 = 半透明玻璃卡而非实底卡）
  - 描述：每勾一项，请补一句「透过它应该能看到什么」——玻璃的本质是「让人知道后面还有东西」，看不到东西的玻璃就是纯模糊色块。
- **A4-7**：整体氛围基调：**通透轻盈**（大面积透光、背景明显可见、玻璃多）vs **沉浸厚重**（背景低调、玻璃克制、深度感来自阴影而非模糊）？你希望别人第一眼评价这个 App 是「干净清爽」还是「精致华丽」？

### A5 边到边（沉浸式全屏）与系统栏
- **背景**：Android 15+ 强制 edge-to-edge（内容延伸到状态栏/导航栏下面）。
- **A5-1**：状态栏/导航栏区域的处理：
  - A. 内容（背景图/顶栏）延伸到系统栏下面，配合背景半透明（沉浸式，B 站风格）
  - B. 系统栏纯色（跟随主题色），内容顶到系统栏下沿
  - 描述：A 在浅色下状态栏文字要深色、深色下要浅色，且顶栏毛玻璃要「接住」状态栏形成一体的玻璃带。这是「高级感」的主要来源之一。
- **A5-2**：状态栏与顶栏是否**合并成一条玻璃带**（背景图从最顶部就开始透，状态栏图标浮在玻璃带上）？还是状态栏独立透明、顶栏在它下面？

### A6 系统返回 / 手势
- **A6-1**：手势返回（从屏幕左/右边缘滑动）的行为：和分区切换（左右滑）**冲突**怎么办？（底部 Tab 是横向滑切，手势返回也是横向——需要定义优先级/边界）
- **A6-2**：Android 预测性返回动画（返回时页面缩小的系统动画）——保持系统默认还是接自定义？

## 二、首页（仓库动态的「主战场」）

### B1 🆕 首页的骨架：分层与滚动
- **背景**：首页 = 横滑 Tab（Trending/News/Issues/PRs）。但「首页」你脑子里是「一眼一个完整页面」还是「可滑动内容流」？
- **B1-1**：**首页第一屏的纵切面**：从上到下是？
  - A. [顶栏] → [横滑 Tab 条] → [Tab 内容列表]（内容从 Tab 条下开始）
  - B. [顶栏] → [搜索热区横幅] → [Tab 条] → [内容]
  - C. 其他（如加入「今日概览卡片」）
- **B1-2**：**横滑 Tab 条**的样式：
  - A. 居中胶囊分页指示（M3 风格：选中项有胶囊/圆底，文字加粗）
  - B. 左边对齐滚动条（文字 Tab，选中加粗 + 主题色下划线）
  - C. 圆角小条（B 站首页那种，选中 Tab 有渐变底）
  - 描述：请描述你见过的、最接近你想要的那种（哪个 App 的哪个 Tab 条）。
- **B1-3**：Tab 内容区**状态**：加载中（骨架屏 vs 转圈）/ 空数据（「今天还没有 Trending」vs 插画）/ 失败（重试按钮形式）——分别想要什么感觉？
- **B1-4**：下拉刷新：手势刷新（M3 重新加载动画）确认？刷新时 Tab 内容整体刷新还是当前 Tab 刷新？

### B2 🔴 数据卡片的样子（你反馈「灰灰的不好看」）
- **背景**：现在 repo 条目卡片用 surfaceVariant 平灰铺底，你嫌灰。核心问题是「卡片如何传达 GitHub 数据的性格」。
- **B2-1**：卡片的**底色策略**，你更倾向：
  - A. **中性底 + 主题色点缀**：卡片用中性 surfaceContainer，但星标 icon、语言色点、fork 数用主题色（primary/tertiary）点亮——克制优雅
  - B. **主题色微渲染的卡片**：卡片背景带 very 淡的主题色调（如 primary 色调的 8% 不透明混合，或 primaryContainer 的浅色），整体偏「粉/蓝」色系
  - C. **对比底 + 描边**：卡片近白/近黑 + 极细 theme-color 描边（发丝线 1px）
  - 描述：A 是 Material 规范主流（颜色克制、语义来自强调）；B 更「有氛围」但浅色下可能显腻；C 最「精致」但设计难度高（描边在深色下要够亮）。请说下你嫌「灰」的**具体感受**——是觉得「没生气、像没做完」还是「和主题无关、像另一个 App」？
- **B2-2**：repo 条目里**必须有哪些元素**（多选）：
  - [ ] 仓库名（主文字，加粗）
  - [ ] 描述（次文字，2 行截断）
  - [ ] 语言色点 + 语言名
  - [ ] ⭐ 星数
  - [ ] 🔱 fork 数
  - [ ] 更新时间（「3 天前」）
  - [ ] 作者/组织头像
  - [ ] 标签（topic，如 「compiler」「android」）
  - 描述：信息密度决定卡片高度；GitHub 网页在 repo 卡片放 名字/描述/语言点/星/更新（很全）；App 一般砍到 名字/描述/星/语言点。你要「信息全」还是「少而精」？
- **B2-3**：卡片的**形状**：圆角大小（8/12/16/20dp）？卡片之间间距？卡片是**左右通栏**（边缘贴屏幕边）还是**内边距悬浮**（屏幕左右留白，卡片成「悬浮片」）？
  - 描述：通栏 = 列表感（GitHub/大多数 App）；悬浮卡 = 玻璃拟真的「片状感」（和你的背景图诉求更搭）。这是「像列表」还是「像卡片集」的分野。
- **B2-4**：卡片**按压反馈**：水波纹？还是轻微缩放 + 变亮/变暗？
- **B2-5**：滑动手势：卡片支持**左滑出操作**（收藏/忽略/稍后看）吗？

### B3 各类 Tab 的内容差异
- **B3-1**：Trending 卡片 = 上述 repo 卡。**News**（无官方 API）你想要的形态是？（GitHub 博客/动态聚合？还是本地拼的「热门事件流」？—— 技术上要自定义数据源）
- **B3-2**：Issues Tab 条目：**issue 卡片**与 repo 卡不同——需要显示：标题 + 所属仓库 + issue 号 + 状态图标（open=绿点/closed=紫点）+ 评论数 + 标签？大概几行？
- **B3-3**：PRs Tab 条目：标题 + 仓库 + PR 号 + 状态（open/draft/merged）+ 评论数？（Draft = 灰色铅笔图标？）

## 三、仓库页（RepoDetail）

### C1 🔴 仓库 Tab（首页「仓库」分区）——T11 未做，先定形态
- **C1-1**：这个分区的**内容**最终是？：
  - A. **我的仓库**（登录用户拥有的仓库，含私有/组织）
  - B. **浏览历史**（最近看过的仓库，快速回访）
  - C. A+B 混合（我的仓库为主，最近浏览置顶）
  - D. **星标仓库**（Stars，之前说要并入「我的」——注意这可能和「我的」里的 Stars 冲突）
  - 描述：底栏叫「仓库」，装「我的仓库」最直觉；但你的收藏星标之前规划放「我的」二级页——需确认不重复。
- **C1-2**：占位页（T11 前）的形态：图标 + 「仓库功能开发中」文案（已实现）？还是临时显示「最近浏览」过渡？用户（真机）看到占位页会不会觉得是 bug？——请定占位策略。

### C2 仓库详情页布局
- **背景**：详情页 = 头部信息 + README + 文件树等。最关键的布局决策：

- 你说「现在的效果（只模糊顶/底栏）不是我要的」——理想中，哪里玻璃？透过玻璃看到什么？整体是「通透轻盈」还是「沉浸厚重」？请尝试描述一个「玻璃感完美」的画面（可以是其他 App 的某个时刻）。

### J3 「请描述理想中的背景图」
- 背景的素材/颜色/亮度/滚动行为？背景和内容是什么「层」关系？（背景显眼地在内容后面 / 只在边缘露出 / 完全陪衬）？深色时它怎样？

### J4 「请描述你希望 README 阅读体验的感觉」
- 是「像在 GitHub 网页上读」还是「像在读一本精美电子书」？信息密度和阅读氛围哪个优先？网页那个「长按/折叠/表格」的完整度 vs App 的「精炼优美」，你各要多少？

### J5 「除了 GitHub、B 站，你希望 App 的气质更像谁」
- 有没有你欣赏的 App/产品——希望这个逻辑上或气质上像它？（可以安卓/iOS/网页任意，如 Notion/Feedly/Telegram/Apple News/即刻/小红书……）请说 1-3 个 + 各像在哪一点。

### J6 「这个 App 在你生活里的角色」
- 每天打开几次？主要用来干什么（刷趋势？查 issue？读 README？写 PR？）？是「工具」还是「消遣」？——这决定整体的信息密度与动效优先级。
